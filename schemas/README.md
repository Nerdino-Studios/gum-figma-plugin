# GAM-206 wire skeletons (major 1)

`wire-v1.schema.json` defines four named shapes under `$defs`: `request`, `snapshot`, `catalog`, and `diagnostic`. `contract-vectors.json` is consumed unchanged by both the plugin TypeScript validator and .NET Contracts tests. These are **shape checks**, not published snapshots or transport operations.

`schemaVersion` is `{ "major": 1, "minor": 0 }`. Reject other major versions; accept nonnegative minor versions through 2147483647 only when all semantic fields remain understood. Unknown fields at the top level or in `schemaVersion` are rejected even with a newer minor. A future use case must add its own named semantic fields and vectors before using them. `extensions` is an optional object whose dotted namespaced keys hold nonempty *informational text only*. It cannot carry layout, mappings, commands, or other operational semantics. Callers must not use it to influence behavior.

The earlier wire `catalog` skeleton still requires empty `controls`; GAM-218 bundles the separate versioned offline `apps/figma-plugin/src/document/builtin-v1.json` data artifact for the verified native frame/text/image slice. Button, TextBox and ScrollViewer are marked unavailable until their adapters are tested. Custom target catalogs remain unresolved. Snapshot v1.4 optionally carries canonical `rootMappings` for selected generated native.frame roots: each root records its catalog ID/revision/mode/control ID and participates in the content hash. Older snapshots remain readable without this field; lower minor versions must reject it. The bridge validates this narrow built-in mapping shape but does not infer or apply unverified control adapters. Snapshot v1.5 adds transitive `components` (generated definitions with typed nodes, or referenced definitions with an explicit control ID and captured placeholder width/height resolved against the selected workspace's SHA-256-hashed catalog at conversion time) and `INSTANCE` nodes keyed by `componentId`. Instance position/visibility are supported overrides; width/height must equal the generated definition until a responsive root rule is verified. Uncontracted child/paint/text overrides block capture and explicit `overrides` fields are rejected. Target-owned references require an existing registered native component; its content hash is target-profile input, not design snapshot content, and target drift invalidates the preview target hash. Referenced placeholders cannot export child visuals or fills. Referenced definitions require a matching trusted target hash at conversion and produce no generated component file. Shared definitions are lowered once; no destination cleanup or ownership pruning is performed by this slice. `nodes` may contain the typed selected-root slice below; later ownership planning remains deferred. The request `operation` is a nonempty opaque name; no operation is executed by this validator. The snapshot ID is nonempty text, not yet a verified content hash. Minimal diagnostic severities are `info`, `warning`, and `error`. Do not treat an accepted skeleton as a complete publishable design or a verified target catalog.

## GAM-215 selected-root thin capture

Snapshot `rootAliases` records explicit root-ID/public-alias pairs (empty when none are supplied), independently of layer names. Snapshot `nodes` now accepts bounded typed `FRAME`, uniform `TEXT`, and raster `IMAGE` objects, with common source ID, nullable parent ID, display name, finite bounds and visibility. Frames include layout mode and clipping; text includes characters, font family/style/size and optional opaque RGB color; images include a SHA-256 asset reference and fit mode. Unknown semantic node properties and unsupported major versions are rejected by both validators. Empty nodes remain valid as a wire shape, **not** a publishable capture. This schema validates shape, not referential integrity, blob bytes or recomputed snapshot IDs; publication must perform those checks later. `captureSelection` hashes canonical selected roots and typed nodes, returns image bytes separately and returns no snapshot when extraction diagnostics are present. This is not a Figma-client compatibility or conversion claim.


## v1.6 approved decorative shapes

A plain solid-filled Figma RECTANGLE is normalized to a leaf `FRAME` with `layoutMode=NONE`, `clipsContent=false`, and its opaque RGB color. The existing native background rule renders it as an editable Gum FilledRectangle; it does not require a raster asset or a new converter rule. Empty rectangles retain transparent geometry. Responsive dimensions use the existing frame rules; image-filled rectangles keep their separate FIT/FILL/CROP restrictions.

Snapshot v1.6 adds `fallback.feature=decorative-shape` for explicitly approved leaf POLYGONs and unsupported decorative rectangle paints/corners. Older versions reject this semantic marker, including inside generated components. Existing `effects/strokes` receipts remain readable. Approval is bound to namespace, node, complete paint/shape properties (including polygon point count), and fingerprint. Noninteractive ancestry, unrotated verified bounds, PNG byte/pixel budgets and mid-capture consistency guards apply. When visible pixels stay inside a whole-pixel node box, export uses full node bounds and preserves the original layout slot, including in auto layout. Cropped overflow still requires integer render dimensions and a non-stack parent. The chosen export mode participates in the approval fingerprint. Neither full screens nor dynamic text/interactive subtrees can use this path. This is an asset fallback, not an editable native polygon claim.
