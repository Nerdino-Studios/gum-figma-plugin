# GAM-211 preview slice (development status)

A paired plugin can publish a selected supported frame, then choose **Render published snapshot in Gum**. The host reads that immutable publication, checks the sample workspace's current input fingerprint, converts frame/text/raster image with the minimal converter, clones the sample into disposable staging, invokes pinned GumCli `check`, `fonts`, `codegen`, and `screenshot --backend monogame`, then stores a bounded PNG outside the registered target. The authenticated artifact route requires workspace, snapshot, target, and artifact ID; the iframe checks the output digest before displaying the image. The registered target is not applied or rewritten. A source or selection change immediately leaves a prior image visible with a stale label. Dynamic-page mode observes only the current page's node changes; changing pages rebinds the observer without loading other pages. The target fingerprint includes registered sample files and pinned tool version but not the machine font binaries or renderer environment; the artifact digest covers bytes produced on this machine, not cross-platform rendering identity.

This is a minimal sample-only preview, not a general registered-project preview or a verified runtime application. No managed target apply, CLI/MCP preview, code compilation, interaction-state preview, component/control mapping, or visual equivalence claim is included. Unsupported conversion diagnostics block the preview. The sample still requires Arial Regular 24 where text is present and a working graphics session. Preview fails if font generation, tool checks, or screenshot fails. The initial screen's dimensions are bounded to 2048×2048 and 4,194,304 pixels; PNG artifacts are bounded to 4 MiB. Source PNG IHDR dimensions are bounded to 4096 per axis, 4,194,304 decoded pixels per unique image, and 16,777,216 decoded pixels across unique images before invoking native tools. Published snapshot blobs remain independently bounded by the publication limits. Preview rewrites staged codegen settings to a staged-only output root before spawning GumCli, ignoring target-configured absolute or traversing output roots.

Run `dotnet test GumBridge.sln`, `python3 -m unittest discover -s tests/architecture -v`, `npm run typecheck --prefix apps/figma-plugin && npm test --prefix apps/figma-plugin && npm run build --prefix apps/figma-plugin`, and `scripts/check-native-sample.sh` with graphics. The native integration test uses the pinned GumCli and a synthetic published frame in the bundled sample, not a real Figma capture. **UNRUN:** this preview workflow in real Figma desktop on macOS or Windows; Windows GumCli/fonts/render; actual selected real-client image/text extraction and preview; native sample application runtime and generated-code compilation. Prior macOS desktop pairing evidence in `docs/compatibility.md` does not establish this preview workflow.
